# External implementation evaluation

The root implementation is adapted from [Team Xero](https://github.com/arnabxero/xero-shopping-sessions), commit `2d5a40b`, MIT license. It uses exact packed identifiers with a fallback interner, per-worker scatter buffers with overflow handling, compact parsed records, event and person partitions, parallel session processing, and parallel Parquet parts. Its STATUS.md reports a 1.35 s official practice score for an earlier commit; this repository's current commit has not been scored.

On an Apple Silicon Mac, a native build of 2d5a40b with a local macOS-only prefetch compatibility change matched all 36 fixtures and both 20M and 60M output tables against the prior implementation. Alternating 20M wall times under desktop load were 10.531 and 8.291 s for the previous implementation, 2.447 and 2.645 s for Xero. A 60M native run took 13.06 s and 5.65 GB peak footprint. These are not controlled scorer measurements. An amd64 Docker build of unmodified upstream code matched the published 1M dev answers with the scorer-style read-only and no-network flags. The 20M and 60M checks compare against the earlier implementation, not an independent official answer.

[Niranjan's MIT-licensed implementation](https://github.com/niranjankumarnk/shopping-sessions) uses overlapped link building, SIMD CSV scanning, partitioned one-pass parsing and a direct Parquet writer. It matched our 20M reference in one 2.06 s local run. Its event and user identifiers rely on truncated hashes rather than full byte equality, so collision cases need an exact fallback before use where correctness must be guaranteed.

[Nathan's implementation](https://github.com/Nathanatpurdue/Databricks---Shopping-Sessions) describes exact packed IDs and a fallback interner, per-thread date caches, batched prefetched lookups, cache-sized partitions and a direct Parquet writer. Its image targets Cascade Lake with AVX-512 and BMI2; those hardware requirements must be established for the scorer. No explicit repository license was found. No code from that implementation was copied here.

The current implementation uses x86-64-v3 (including AVX2 and BMI2); the track's listed limits do not by themselves establish CPU instruction support. A successful emulated Docker test on an Apple host is not proof that every scorer host supports the target. Repeated scorer-class Linux benchmarks, collision and overflow tests, and the current commit's official practice score remain necessary.
